# 懿珠宝管理软件开发规范及需求说明

> 文档版本：v1.0  
> 适用范围：懿珠宝管家（jewelry）业务应用插件  
> 参考依据：项目根目录《应用插件开发说明.md》、`demo` 目录中的电脑端/手机端界面原型

---

## 一、项目概述

懿珠宝管家是为珠宝零售门店打造的一站式业务管理应用，覆盖商品档案、库存、销售、定金尾款、借货、客户、维修、采购与委外加工等核心业务环节。系统需同时支持**电脑端（PC）**与**手机端（Mobile）**访问，并根据屏幕尺寸与方向的差异自动切换不同的设计布局。

| 项 | 说明 |
| --- | --- |
| 插件标识 | `jewelry`（插件以 `jewelry` 为根目录） |
| 插件名称 | 懿珠宝管家 |
| 技术栈 | Python3 + Vue3 + SQLite3 |
| 终端适配 | 支持电脑端（宽屏、多栏、表格化）、手机端（窄屏、单列、卡片化 + 底部 Tab） |
| 多语言 | 支持简 / 繁 / 意 / 英 / 日 / 韩六种语言，均已实现完整翻译（详见 4.5） |
| 样例目录 | `plugins/jewelry/demo/`（界面原型） |

---

## 二、技术架构与目录规范

插件遵循「后端（Python/FastAPI）+ 前端（Vue3 SPA）+ SQLite 数据库」三层结构，打包为特定规范的插件压缩包，供业务平台加载、初始化、启动与网关透传访问。

### 2.1 插件包目录结构（以 jewelry 为根）

```
jewelry/
├── plugin.json            # 核心元数据（必须位于根目录）
├── main.py                # 后端主程序（FastAPI / 服务入口）
├── upgrade.py             # 数据库结构迁移脚本（可选）
├── requirements.txt       # 后端依赖清单
├── frontend/              # 前端 Vue3 应用资产
│   ├── index.html         # SPA 入口
│   ├── assets/            # 打包后的 JS / CSS 资源
│   └── vue3/              # Vue3 运行时依赖
└── promo/                 # 推广页（可选，独立子目录，纯静态）
    ├── index.html
    └── style.css
```

### 2.2 plugin.json 必需字段

| 字段名 | 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `id` | String | 必需 | 插件标识 `jewelry` |
| `name` | String | 必需 | 懿珠宝管家 |
| `softwareVersion` | String | 必需 | 当前软件版本号 |
| `dataVersion` | String | 必需 | 数据结构版本号 |
| `promo` | String | 可选 | 推广页相对路径（`promo/index.html`），仅在推广时必需 |
| `entry` | String | 必需 | 后端服务入口（`main.py`） |
| `scripts` | Object | 可选 | `init`/`upgrade` 脚本路径 |

> ⚠️ `promo` 字段安全红线：推广页必须为 `.html` 且位于独立子目录（如 `promo/index.html`），严禁放在包根目录，否则将暴露 `plugin.json` 与后端代码。

### 2.3 技术约束

- 后端：Python3 + FastAPI（支持插件主进程独立运行）。
- 前端：Vue3（单页应用，一个入口适配电脑端与手机端）。
- 数据库：SQLite3，每个租户一份独立数据库文件，文件位于平台指定的租户库目录。
- 前后端分离：前端仅通过 API 网关 `/gw/` 链路访问后端接口，后端无需关心网关前缀与租户路径拼接。
- 业务数据与平台数据严格隔离：插件不直接访问平台数据库，只操作自身租户库。

## 三、环境与鉴权契约

插件后端必须遵循平台「平台免密凭证（SSO Token）+ 插件原生凭证（Business Token）」双轨制鉴权契约。

1. **轨道 A：平台单点/穿透跳转（SSO Token）**
   - 平台携带 SSO Token 跳转到 `/app/jewelry/{租户ID}/`。
   - 前端获取 Token 后交给后端核验；后端全局拦截校验合法后免密放行，并建议换签为插件自身 Business Token。
   - SSO Token Payload 必含 `iss / iat / exp / sub / tid / mode / role` 等字段。

2. **轨道 B：业务用户日常登录（Business Token）**
   - 用户直接访问 `/app/jewelry/login` 输入账号密码登录。
   - 后端校验通过后调用平台内网 API 核对订阅状态，签发插件 Business Token（默认有效期约 2 小时），并将平台返回的功能清单 `features` 打包进 JWT Payload。

### 3.1 操作模式与插件响应

| 模式 | `mode` | 特征 | 插件响应 |
| --- | --- | --- | --- |
| 常规业务 | `NORMAL` | `tid` 为真实租户 | 连接真实业务库，正常执行业务 |
| 试运行上帝模式 | `SANDBOX` | `tid=tenant_trial`、平台管理员 | 强制连接沙箱虚拟库、最高权限，**拦截并 Mock 短信/邮件/第三方扣费** |
| 生产运维穿透 | `PRODUCTION_SUPPORT` | 真实租户 + 运维人员 | 连接真实库、最高权限，**强制记录每一笔修改的审计日志，前端渲染醒目红色警告边框** |

### 3.2 前端动态适配订阅功能

- 登录成功后，后端返回 `features` 功能清单，前端存入全局状态（Pinia）。
- 界面渲染时必须根据该清单动态**隐藏或锁定**未订阅的高级功能菜单与操作按钮。

## 四、界面布局与响应式设计

### 4.1 总体要求

页面需支持电脑端与手机端应用。由于屏幕大小与方向不同，采用**两套设计布局**：

- **电脑端（PC）布局**：侧边栏导航 + 顶部工具栏 + 多栏内容区；适合宽屏桌面，采用表格化、多列信息展示。
- **手机端（Mobile）布局**：顶部应用栏 + 单列卡片流 + 底部 Tab 导航；适合窄屏与竖屏触控，采用卡片式、流式布局。

### 4.2 断点与适配策略

- 以 `max-width` 媒体查询（如 768px/1024px）判定终端形态。
- 电脑端优先展示宽屏布局，手机端优先展示窄屏布局。
- 确保横竖屏切换、不同分辨率下体验一致；手机端需适配安全区（`env(safe-area-inset-*)`）与触摸手势。

### 4.3 视觉设计规范（懿珠宝品牌风格）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--gold` | `#C9A961` | 主金色，品牌点缀 |
| `--gold-dark` | `#9C7B3A` | 金色深色，文字强调 |
| `--wine` | `#5C2233` | 酒红色，主品牌色 |
| `--cream` | `#FBF6EC` | 米白底色 |
| `--text` | `#3D2B1F` | 主文字色 |
| `--border` | `#EADFC8` | 边框线色 |

- 统一字体：中文使用「苹方 / 微软雅黑」，数字与金额可使用衬线字体（如宋体）强调。
- 金额展示格式：`¥` + 千分位（如 `¥18,600`）。
- 全局统一样式组件：按钮（金/酒红/幽灵）、标签、状态圆点、卡片、弹窗/底部抽屉、Toast 提示等。

### 4.4 主要界面清单

#### 电脑端界面
- 登录页、经营看板、商品管理、库存管理、销售开单、定金尾款、借货管理、客户管理、操作日志。
- 商品管理 / 库存管理中含 **标签打印（内置模板 + 模板设计 + 打印预览）** 与 **RFID 批量隔空盘点**入口。

#### 手机端界面
- 登录页、经营看板、商品管理、库存管理、销售单、定金尾款、借货管理、维修管理、采购管理、委外加工、客户管理、操作日志、我的。

> 手机端相比电脑端额外包含维修、采购、委外加工等移动场景强相关功能模块。

### 4.5 多语言支持方案（i18n）

系统界面需支持多语言。目标语言集与当前实现进度如下：

| 语言 | 语言编码 | 状态 |
| --- | --- | --- |
| 简体中文（默认） | `zh-Hans` | ✅ 已实现 |
| 繁體中文 | `zh-Hant` | ✅ 已实现 |
| 意大利语（Italiano） | `it` | ✅ 已实现 |
| 英语（English） | `en` | ✅ 已实现 |
| 日语（日本語） | `ja` | ✅ 已实现 |
| 韩语（한국어） | `ko` | ✅ 已实现 |

#### 4.5.1 实现原则

- **单一资源 + 字典切换**：仅需维护一套页面/应用代码，语言内容以「key → 语言字典」的方式组织，运行时按需切换，**无需为每种语言复制页面**。
- **回退机制**：维护「语言 → 可读字典」映射表（`LANG_MAP`）。目标语言缺词或未实现翻译时，自动回退到简体中文，保证页面永不出现空白文案。
- **持久化**：用户手动选择的语言写入 `localStorage`，下次访问自动恢复。
- **自动识别**：首次访问按浏览器语言自动选择（`zh-Hant`/`it`/`ja`/`ko`/`en` 优先匹配，其余默认简体）。繁体中文优先适配 `zh-TW`/`zh-Hant`。
- **标签归一化**：真实语言代码（如 `zh-Hans`）仅用于持久化与数据层；对外展示标签（`LANG_LABELS`）以用户可读形式呈现（如「简体中文 / Italiano / English」）。
- **动态文案随语言切换**：静态文本、`placeholder` 占位符、动态提示（Toast/确认框）均通过统一字典键读取，切换语言时一并刷新。

#### 4.5.2 前端实现约定

- 静态文本：通过 `data-i18n` 属性绑定字典键，由 `applyI18n()` 统一注入。
- 含 HTML 的富文本（如含 `<b>/<small>/<br>`）：通过 `data-i18n-html` 绑定，注入时保留内联标签。
- 表单占位符：通过 `data-i18n-ph` 绑定，写入 `placeholder`。
- 动态消息（Toast、弹窗提示）：调用翻译函数 `t(key)` 取词，取词失败自动回退简体。
- 语言切换控件：采用**下拉菜单**（支持 6 种语言），当前语言高亮，点击外部或按 `ESC` 收起。
- 新增语言：在语言字典对象中追加一套完整翻译即可，页面代码无需改动。

> 推广页（`promo/index.html`）当前已落地上述方案，可直接作为前端 SPA 与后续界面实现的多语言设计参考。

### 4.6 多租户店铺/企业介绍架构（一个业务服务多个企业租户）

**设计原则**：一个 `jewelry` 应用同时服务多个企业/店铺租户，插件包是**共享且只读**的一份代码，任何租户私有的「店铺/企业介绍」**一律不得写入插件包**，必须落在各租户自己的数据与媒体目录中，实现「共享代码 + 租户私有数据」彻底分离。

#### 4.6.1 归属划分

| 内容 | 归属 | 存放位置 |
| --- | --- | --- |
| 企业/店铺介绍文本（名称、简称、简介、Slogan、联系人、电话、地址、营业时间、经营品类、企业简介长文等） | 租户私有 | 租户库 `tenant_profiles` 表（每租户一份 SQLite，见六章） |
| 店铺 Logo、门头照、宣传图等图片/文件 | 租户私有 | 平台分配的**租户媒体/上传目录**，路径含租户标识，不入插件包 |
| 店铺主页展示代码、介绍信息渲染组件 | 共享 | 插件前端 SPA（Vue3）内的「店铺主页」视图 |
| 编辑器（录入/图片上传/预览/发布） | 共享 | 插件前端 SPA + 后端 `/gw/jewelry/*` 接口 |

#### 4.6.2 租户在高权限模式下的上下文

- 后端从请求头（平台透传的插件业务 Token / 租户解析头）定位当前 `租户ID`，动态连接**该租户**的数据库并返回 **该租户** 的介绍。
- 同一套后端代码，根据租户上下文加载不同 `tenant_profiles`；不同租户的图片经媒体目录 URL 前缀（含租户标识）区分，互不串访。
- 平台管理员在 `PRODUCTION_SUPPORT` 模式下可切换任意租户，编辑其介绍时照常写入审计日志。

#### 4.6.3 图片/媒体目录规划（示例）

```
租户媒体根目录/
├── {租户A}/            # 如 tenant-a
│   ├── logo.png        # 店铺 Logo
│   ├── storefront.jpg  # 门头照
│   ├── gallery/        # 宣传图/案例图
│   └── site/           # 企业迷你网站根目录（静态 HTML 包解压于此，可选）
│       ├── index.html
│       ├── index.css
│       └── img/
└── {租户B}/
    ├── logo.png
    └── storefront.jpg
```

- 媒体文件上传经后端鉴权后写入，返回的相对 URL 含租户标识；介绍表仅存相对路径，前端按租户媒体基地址拼装完整 URL。
- 该目录属于租户私有可写区，**与插件包目录、promo 推广页目录严格隔离**。

#### 4.6.4 对外展示

- 企业需要向平台/市场对外展示店铺主页时，由 SPA 的「店铺主页」视图读取该租户介绍生成公开展示页（如 `/app/jewelry/{租户ID}/about` 或市场挂载的租户名片）。
- 是否公开展示、展示哪些字段，由租户在介绍编辑器中控制。

## 五、业务需求与功能模块

### 5.1 经营看板（Dashboard）

- 展示核心经营指标：**在售商品数、库存成本、今日销售、未收欠款**。
- 展示「近 6 月销售趋势」图表与「待办提醒」（如定金催促交付）。
- 展示最近销售单列表。
- 指标口径需有明确说明（如「在售商品」= 状态为“在库”的商品数）。

### 5.2 商品管理（Products）

- 商品档案字段：编码、名称、品类（黄金/钻石/翡翠/铂金/彩宝）、材质、克重、尺寸、证书号、成本价、零售价、所在门店、状态、**RFID 芯片 EPC（唯一识读号）**。
- **一物一码**：每件珠宝独立建档，编码唯一，库存精确到单件；可为其**绑定 RFID 标签（写入芯片 EPC）**，实现隔空感应识别。
- **状态流转**：在库 → 已定（收定金）→ 已完成（付尾款转正式单）；在库 → 借出（调拨登记）。
- 支持新增商品、查看详情、开单。
- **RFID 标签打印**：通过 RFID 打印机将商品编码、名称、材质、克重、售价、条码号及**芯片 EPC** 打印写入标签，供后续隔空盘点与追溯。
- **毛利** = 售价 − 成本；毛利率 = 毛利 ÷ 售价。

### 5.3 库存管理（Inventory）

- 库存状态统计：正常在库、已定锁定、借出在外、库存总成本。
- **入库登记**：入库日期可自由选择，支持补录历史单据。
- **复制入库**：支持一键复制历史入库单，快速入库。
- **多模式盘点**：
  - **普通条码盘点**：通过扫码枪逐件扫描条码核对账实。
  - **高频 RFID 批量隔空盘点**：通过高频 RFID 读写器/蓝牙 RFID 手持机（扣动扳机）批量感应识别范围内所有芯片标签，无需逐件触碰；实时显示「已感应标签数」「账面库存」「盘盈」「盘亏」，逐件列出「芯片 EPC / 商品 / 在库状态 / 盘点结果」，自动匹配账实并**自动生成盘点差异单**。
- **库存扣减机制**：普通销售即扣；定金单不扣库存，付清尾款后转正式单才扣减。

### 5.4 销售开单（Sales）

- 支持普通开单、定金下单；开单日期可自由选择。
- **单据冻结**：开单后商品明细与售价不可修改；客户姓名与电话可随时修改、无需退单。
- **冲红重开机制**：调整货品或金额时先冲红作废原单，系统自动还原库存后重新下单。
- **库存扣减**：普通销售单生效立即扣减在库商品。
- 状态：已完成 / 欠款 / 已冲红。

### 5.5 定金尾款（Deposits）

- **定金下单不扣库存**：可选择在库商品（锁定为“已定”），也支持无现货定制下单。
- **尾款转正式单**：客户付清尾款后自动生成正式销售单并扣减库存。
- **交期提醒**：在承诺交付日基础上可手工设置提前提醒天数（默认提前 7 天），到期自动提醒店员催交付。
- **违约冲红**：定金单可冲红，锁定商品恢复在库。

### 5.6 借货管理（Loans）

- **借进的货**：视同进货赋予独立编号，独立核算，不占正常采购成本。
- **借出的货**：通过调拨操作从在库转入借货栏，与正常销售出库隔离。
- **归还核销**：借进归还直接核减；借出归还自动恢复至正常在库。
- 统计：借入中、借出中、近期到期、借货总值。

### 5.7 客户管理（Customers）

- 客户字段：姓名、手机号、会员等级（金卡/银卡/普通）、累计消费、欠款、生日、偏好。
- **累计消费与欠款**：自动归集销售单消费，未付清款项自动计入客户欠款。
- **信息互通**：销售单开出后允许修改客户信息，自动同步更新客户库。
- 支持发催收账单。

### 5.8 维修管理（Repairs，手机端重点模块）

- **接件登记**：记录客户、首饰、故障描述、预估费用、承诺交付日。
- **状态流转**：待维修 → 维修中 → 待取件 → 已完成。
- **费用记录**：完成后填入实际收费，计入客户累计消费。

### 5.9 采购管理（Purchases，手机端重点模块）

- **采购下单**：记录供应商、商品、数量、成本单价、预计到货日。
- **状态流转**：待发货 → 已发货 → 已入库（入库后自动增加库存）。
- **付款登记**：支持分次付款，未付清自动计入应付账目。

### 5.10 委外加工（Outsourcings，手机端重点模块）

- **发料**：记录金料克重、金价、加工费、加工厂、预计交货日。
- **成本计算**：成本 = 金价 × 克重 + 加工费。
- **收货入库**：收货后自动入库，可用于定制订单交付。
- 状态：加工中 / 已收货。

### 5.11 操作日志（Logs）

- 对创建、开单、收定、冲红、调拨、借货、入库、维修等关键业务全程留痕。
- 对 **RFID 标签打印**与 **RFID 隔空盘点**行为单独记录（含芯片 EPC、差异结果）。
- 记录：时间、操作人、门店、操作类型、目标对象、结果。
- 支持导出（如 CSV），日志不可篡改。

### 5.12 RFID 打印机与批量隔空盘点设备

系统需对接 RFID 相关硬件，为商品提供「写入即识别」的标签管理与批量隔空盘点能力。

| 设备类型 | 说明 | 应用场景 |
| --- | --- | --- |
| RFID 打印机 | 打印且同时写入芯片 EPC 的标签打印机（如 TSC 等），支持珠宝对折标签/挂绳标签 | 商品建档时打印并写入 RFID 标签 |
| 高频 RFID 读写器 | 台式/柜式高频读写器，覆盖柜面及保险柜范围内标签 | 电脑端批量隔空盘点 |
| 蓝牙 RFID 手持机 | 便携式，扣动扳机触发扫描 | 手机端移动盘点 |

**功能要求：**
1. **RFID 标签打印**：打印时写入商品编码、名称、材质、克重、售价、条码号与唯一芯片 EPC；手机端可选择打印份数并与蓝牙标签机连接后输出。
2. **批量隔空盘点**：读写器/手持机启动高频扫描，隔空批量感应范围内所有芯片标签，实时回传「已感应标签数」；界面逐件展示「芯片 EPC / 商品 / 在库状态 / 盘点结果」，并汇总「账面库存 / 盘盈 / 盘亏」。
3. **差异处理**：自动按账实自动匹配，生成盘点差异单（盘盈/盘亏明细），并将差异结果与盘点记录写入 `inventory_logs` 与操作日志。
4. **双端入口**：电脑端以「RFID 盘点」弹窗提供批量扫描与启动高频扫描；手机端以底部抽屉提供同类能力。 

### 5.13 打印标签模板设计（电脑端）

电脑端提供**标签模板设计与打印管理**能力，用于珠宝纸质/RFID 标签的批量排版与输出。

**支持的内置模板**

| 模板 | 尺寸 | 适用 | 构成 |
| --- | --- | --- | --- |
| 珠宝对折标签 | 75mm × 25mm | 普通珠宝吊牌 | 正面：品名+材质克重+售价；折内：证书号+条码 |
| 挂绳条码标签 | 80mm × 30mm | 挂绳吊牌/柜面展示 | 品名、条码、售价、价格卷 |
| RFID 芯片标签 | 依打印机规格（如 45mm × 30mm 等） | 需隔空盘点商品 | 品名、售价、条码、芯片 EPC |

**标签布局与元素**（电脑端可视化排版）
- 可配置元素：商品名称、编码、品类、材质、克重、尺寸、证书号、售价、条码（一维码）、生肖/属性图标、门店名称与二维码、RFID EPC。
- 提供字段拖拽/上下组合排版、每张标签打印份数、每行标签数量与间距设置。
- 打印前提供**打印预览**（所见即所得），可实时查看标签实际输出效果。
- 支持按「单件打印」「批量打印（按筛选结果）」两种方式。

**打印机配置**
- 可管理多台打印机：前台热敏标签机（TSC 244）、便携/蓝牙标签机、RFID 标签打印机。
- 每种打印机可绑定默认模板、默认标签尺寸与打印份数。
- 电脑端通过 USB/网络/驱动连接打印，手机端通过蓝牙连接便携机输出。

**RFID 写入联动**
- 选择 RFID 打印机并存在 `rfid_epc` 时，打印过程中自动向芯片写入 EPC 并回写商品状态，打印完成后提示「打印成功，已写入芯片 EPC」。
- 打印成功记录写入操作日志（时间/操作人/门店/目标/EPC）。

**实现要求（电脑端）**
- 在「商品管理 → 打印标签」与「库存管理 → 打印标签」入口调出模板；商品详情也提供单件打印。
- 以弹窗承载模板选择、字段排版、份数/打印机设置与实时预览。
- 采用 CSS/HTML 精确还原标签尺寸与裁切标记，保证打印边框、留白、条码可正常读取。

### 5.14 企业迷你网站（Business Mini-Site）

面向**无独立网站的小微珠宝店铺**，以**纯静态 HTML 包上传**方式为每个租户提供可对外公开的企业网站。企业将现成的整站（HTML/CSS/JS/图片）打包上传，后台解压到该租户专属目录，平台按静态站点伺服，无需自建网站、买域名（企业于平台内自建 / 可视化托管建站为**后期考虑**，本期不实现）。

> 该模块与 4.6「多租户店铺/企业介绍」相衔接：店铺简介、Logo、门头图等基础信息来自 `tenant_profiles` 与租户媒体目录，站点作为对外公开的线上名片。

**功能要求：**
1. **上传与部署**：租户通过管理接口上传**现成静态 HTML 网站包**（`.zip` 等），上传后由后台校验并解压到该租户专属站点目录，即完成部署。
   - 站点目录归属：路径含租户标识，`站点根目录/{租户ID}/`，解压内容只允许落于该租户目录内，跨租户与越权访问被平台拦截（返回 HTTP 404）。
   - 校验与安全：解压前做**白名单过滤**（仅 `.html/.htm/.css/.js/.png/.jpg/.jpeg/.svg/.webp/.gif/.ico/.woff/.woff2/.ttf` 等静态资源），**拒绝并清理**可执行脚本、`..` 路径穿越、超大文件与解压炸弹（zip-slip 防护），超限文件直接隔离或拒绝。
2. **对外访问**：租户站点地址为 `/app/jewelry/{租户ID}/site`；租户 `site/` 目录存在 `index.html` 即视为已发布并对外伺服，未上传则视为未发布（访问给出提示）。删除站点目录即下线。
3. **数据与权限**：
   - 站点全部为静态文件，**不使用数据库管理**；站点上线与否由文件系统是否存在判定（见上）。
   - 空间严格隔离：跨租户站点目录互不访问；`PRODUCTION_SUPPORT` 模式可管理任意租户站点目录并写审计日志。
4. **权限与审计**：上传/解压/下线操作计入操作日志并留痕。

#### 5.14.1 商品橱窗公开规则（Showcase Visibility）

「商品橱窗」负责把店铺**可公开**的商品展示给访客，必须做到「可展示的隐私可控、口径清晰」。

**商品公开性来源**
- 商品是否上橱窗由店铺显式控制，**默认不上架**；仅在开启「允许上橱窗」后才可对外展示（避免库存、成本等敏感信息外泄）。
- 商品主页展示仅含公开字段，**绝不展示**成本价、采购价、日志等内部数据。

**公开字段白名单**
- 允许展示：名称、品类、材质、克重、尺寸、公开售价、证书号（可选）、图片（媒体目录）、门店/在售状态。
- 禁止展示：成本价、成本毛利率、渠道、内部备注、操作日志。

**公开范围筛选**
- 可按 品类 / 克重区间 / 价格区间 / 门店 / 是否在库 组合筛选橱窗商品。
- 仅「在库 + 允许上橱窗」商品默认进入橱窗；已售/已定/借出商品不展示，或按店铺策略显示「已售罄/已定」占位。

**同步与更新**
- 商品上/下橱窗状态可在商品管理或橱窗编辑器维护；前端购物橱窗实时按最新公开状态渲染。

#### 5.14.2 预约到店（Visit Appointment）

「联系/预约」版块允许访客**在线发起到店预约**，潜在客户留下意向，由店铺跟进。

**预约要素**
- 访客提供：姓名、联系方式（电话/微信）、意向品类、意向时间（到店日期与时段）、备注。
- 可选：意向商品（若在橱窗看到具体款式，可带过来）或「到店看货/定制咨询」类型。

**隐私与防骚扰**
- 默认隐藏手机号后 4 位或提供「留微信」选项；联系方式仅店铺可见。
- 提供图形验证码/频率限制，防机器刷单。

**跟进流转**
- 新增预约进入店铺的预约列表，状态：待联系 → 已联系 → 已到店 → 已成交 / 已关闭。
- 到店/成交后可与客户档案（`customers`）关联建档，沉淀为可跟进线索。
- 记录操作日志，`PRODUCTION_SUPPORT` 模式可查看任意租户预约并留痕。

**对内/对外差异**
- 对外：仅展示预约入口与表单（静态浏览，**不提交业务表单**，跳转或标记意愿）。
- 对内：店铺在后台查看预约列表、跟进并标记状态，联动客户管理。

## 六、数据库设计（SQLite3）

> 以下为逻辑表结构设计，具体 SQL 以 `upgrade.py` 迁移脚本为准。所有表需带主键，金额字段用 `REAL`/整数分存储。

| 表名 | 主要字段 | 说明 |

| `stores` | id, name, code, owner | 门店 |
| `products` | id, code, name, category, material, weight, size, cert, cost, price, status, store_id, **rfid_epc**, showcase_public | 商品档案（含 RFID EPC、是否允许上橱窗） |
| `customers` | id, name, phone, level, total_amount, due_amount, birthday, preference | 客户档案 |
| `sales` | id(单号), customer, product, amount, paid, method, biz_date, type, status | 销售单 |
| `deposits` | id, customer, phone, product_id, product, total, deposit, balance, promised_date, reminder_days, status, created | 定金尾款单 |
| `loans` | id, direction(in/out), product, code, party, qty, loan_date, due_date, status | 借货记录 |
| `repairs` | id, customer, phone, item, issue, est_fee, actual_fee, receive_date, promised_date, done_date, status, technician, remark | 维修单 |
| `purchases` | id, supplier, product, qty, cost, order_date, expected_date, received_date, status, paid | 采购单 |
| `outsourcings` | id, factory, product, material, weight, gold_price, labor_fee, send_date, expected_date, received_date, status | 委外加工单 |
| `label_templates` | id, name, size_width, size_height, layout(json), cols, gap, copies, default_printer, is_rfid | 打印标签模板（电脑端模板设计与打印配置） |
| `inventory_logs` | id, product_id, epc, type(in/out/scan/rfid), qty, ts, operator | 库存流水 / RFID 隔空盘点记录 |
| `operate_logs` | id, time, operator, store, action, target, result | 操作审计日志 |
| `appointments` | id, tenant_id, name, contact, contact_type(phone/wechat), category, product_id, want_date, want_slot, remark, status(pending/contacted/arrived/done/closed), created | 到店预约（来源企业迷你网站） |

**数据结构升级约定**：
- `dataVersion` 未变化则沿用上一版本号；结构变化时 `dataVersion` 等于软件版本号。
- `upgrade.py` 在数据库升级时执行结构迁移，并保留原有业务数据。

## 八、开发与交付规范

1. **插件根目录**：所有源码、配置、前端资产均位于 `jewelry` 目录。
2. **配置合规**：`plugin.json` 字段完整、版本号与数据结构版本号规范。
3. **响应式保真**：前端必须同时实现电脑端与手机端两套布局，整体风格与 `demo` 原型一致（金色 + 酒红品牌色）。
4. **安全**：
   - 凭据不写入源码与日志；密钥不入库、不上传。
   - 前端根据 `features` 隐藏/锁定未订阅功能。
   - 按 mode（NORMAL / SANDBOX / PRODUCTION_SUPPORT）执行对应响应策略并记录审计。
5. **数据隔离**：不触碰平台数据库，仅操作本插件租户 SQLite 库。
6. **多端可用性**：分别在电脑浏览器与手机端（含横竖屏）测试关键业务路径。
7. **多语言覆盖**：切换简 / 意 / 英 时，所有静态文案、占位符与动态提示均随之切换，无残留简体；繁 / 日 / 韩回退简体正常。
8. **维护文档**：本说明随版本更新，保持与实际实现一致。
