# 经营看板高价值模块扩展方案

## Context
用户要求给珠宝云「经营看板」补充 5 类模块。经确认的决策：
- ①金价栏：接**新浪国际黄金（伦敦金 hf_XAU）实时接口** + 现有门店零售克价（biz_config.gold_price 手填）
- ②品类占比：做**环形图**（现有接口 `/api/dashboard/category-sales` 已支持区间，前端现为条形图，升级为环形）
- ③客户关怀：**新增真实结婚纪念日字段**（需迁移 dataVersion 递增）+ 生日 + 售出满一年保养提醒
- ④员工效能：**本次不做**（用户明确）
- ⑤滞销库龄+盘点预警：库龄>180 天未动销的件数/成本金额 + 最近一次盘点盘盈/盘亏数

涉及文件：`plugins/jewelry/main.py`、`db.py`、`plugin.json`、`frontend/app.js`、`index.html`、`app.css`、`i18n.js`。

## 1. 金价与零售克价栏

**后端**（main.py 看板区 L1326 附近新增）：
- `GET /api/dashboard/gold`：
  - 拉新浪 `https://hq.sinajs.cn/list=hf_XAU`（须带 `Referer: https://finance.sina.com.cn` 头，GBK 解码），取伦敦金 USD/盎司；同时拉 `list=USDCNY` 汇率
  - 换算：`元/克 = usd_oz * fx / 31.1035`
  - 进程内缓存 5 分钟（模块级 dict + 时间戳）；**网络失败回落**：上次缓存值 → 无缓存返回 `intl:null`
  - 返回 `{intlPrice, intlTime, retailPrice(=biz_config.gold_price), retailUpdated}`
  - 只读查询、无对外副作用，SANDBOX 允许（失败即静默降级）
- 用标准库 urllib（项目无 requests 依赖约定则确认；main.py 已有 webhook 用 urllib/httpx 的先例，跟随现状）

**前端**：
- KPI 卡上方加一条 `.gold-bar`：🌍 国际金价 $/oz + ¥/克 ｜ 🏪 门店零售克价 ¥/克（点击跳转 biz-config 设置，导购可改）
- `loadDash` 并行请求；ST 加 `goldData`
- 国际价为 null 时显示「—（获取失败，点击重试）」，零售价为 0 时提示「未设置」

## 2. 品类销售占比环形图

- 后端不动（`/api/dashboard/category-sales` 已按 start/end 出数，`loadDash` 已传区间）
- 前端把现有条形图（index.html L170-179）替换为 **SVG 环形图**：
  - app.js 加 `donutPaths` computed：按 catSales.items 的 pct 生成 `stroke-dasharray` 圆弧段（用 `<circle>` stroke 分段，避免模板复杂表达式踩 Vue global build 黑名单）
  - 中心显示区间总销售额；右侧图例沿用现有 `catText()` 品类翻译 + 金额/占比
  - 配色用现有 `catc0..catc5` 六色变量
- 移动端同组件自适应（宽度 100%）

## 3. 客户关怀提醒（含纪念日迁移）

**迁移（AGENTS.md §4 硬规矩）**：
- `db.py`：SCHEMA customers 表定义加 `anniversary TEXT DEFAULT ''`；`migrate_schema` alters 列表加 `("customers","anniversary","TEXT DEFAULT ''")`（幂等）
- `plugin.json`：`dataVersion` 1.2.0 → **1.3.0**（结构变更必须递增）
- `scripts/upgrade.py` 无需改（已走 migrate_schema 幂等补列）；`scripts/init.py` 新库走 SCHEMA 自带

**后端**：
- `CustomerIn` 加 `anniversary: str = ""`；`customer_create/update` SQL 补列
- `dashboard_reminders`（L1386）返回新增 `care` 列表，三类合成（各 LIMIT 8，按紧迫度排序）：
  - 生日：`birthday` 的 MM-DD 在未来 30 天内（含已过本月→明年处理，SQL 用 `strftime('%m-%d')` 比较，Python 侧算窗口更稳）
  - 纪念日：`anniversary` 同上
  - 保养：`sales`（status!='已冲红'）join sale_items，`biz_date` 满 365±30 天且商品非冲红 → 提醒清洗保养
  - 每条 `{type:'birthday|anniversary|care', customer, phone, date, extra}`

**前端**：
- 待办提醒区（index.html L182-190）追加 care 组：新 tag 样式 `rt-care`（生日🎂/纪念日💍/保养✨），`todoCount` 计入 care 数
- 客户表单（PC+移动端）加「结婚纪念日」date 输入（生日旁），i18n 三语

## 4. 滞销库龄与盘点预警

**后端**（main.py 新增 `GET /api/dashboard/risk`）：
- 滞销：`products WHERE status='在库' AND (store_id=? OR store_id=0) AND julianday('now','localtime')-julianday(created)>180` → count、SUM(cost)
- 成本权限：沿用现有模式（无 can_view_cost 时 cost 返回 null，前端显 `***`）
- 盘点异常：最近一次 `stocktakes` 的 `surplus_count/shortage_count/abnormal_count` + created
- 返回 `{aging:{count,cost}, lastStocktake:{batch_no,surplus,shortage,abnormal,created}}`

**前端**：
- KPI 行下加一条 `.risk-bar`（两枚警示卡）：⏳ 滞销 180 天+ N 件/金额（点击跳库存管理）；📡 最近盘点 盘盈X 盘亏Y（无盘点记录则隐藏）
- 金额 null 显 `***`（复用 `isCostVisible()`）

## 7. 风险与遗留
- 新浪接口无官方 SLA：缓存+降级兜底，不影响开单主流程
- 保养提醒以 `sales.biz_date` 起算，历史种子数据会产生一次性提醒（可接受）
- 员工效能模块按用户决定不做；如后续要做需新表+迁移
