# 珠宝云：销售开单增强 / 门店调拨 / 库位与证书 / 经办人 - 产品需求文档

## Overview
- **Summary**：为 jewelry 插件补齐四项门店日常运营能力：开单日期确认、门店间商品调拨（两步制+部分收货）、商品存放位置与证书存放位置（库位主数据）、销售单经办人（分类+人员）。
- **Purpose**：让多门店实物流动可追踪、商品/证书取放可定位、销售业绩可按经办渠道归类。
- **Target Users**：门店店员/店长（单租户多门店，当前不做门店级数据权限隔离）。

## Goals
- 商品可在门店间发起调拨，在途冻结，调入方扫码验货后部分入库、差异退回且原因必录，全程留痕。
- 商品有明确的「存放位置」「证书存放位置」库位归属，可按库位查货、可一键筛出未配证书商品。
- 销售单记录经办渠道类别（店员/主播/代理/代销，可配置）与可选具体经办人，支持筛选统计与小票展示。
- 开单日期默认当天、可改选（现状已具备，本期验证固化）。

## Non-Goals
- 库位三级层级（柜→层→格）与库位容量/占用率管理：本期仅扁平库位。
- 门店级权限隔离（A 店账号看不到 B 店单据/商品）：维持现状，任何登录用户可操作全部门店，单据记录操作人与门店。
- 调拨单与销售小票以外的新打印模板（调拨单纸质打印后续迭代）。
- 库位/经办人类别的多语言名称维护界面（分类名首期直接存中文单值，与现有部分基础数据做法一致）。
- 调拨在途商品的 EPC 重写/标签重打。

## Background & Context
- 现状代码结论（2026-10-06 调研）：
  - `sales.biz_date` 后端（SaleReq.biz_date，默认今天）与前端（`<input type="date">`，默认当天）**均已实现**。
  - 调拨完全空白：无表、无 API、无界面；文档中「调拨」仅指"借出"语义。
  - `products.cert`（证书编号）已存在；无任何位置字段；商品列表仅支持 q/status 筛选。
  - sales 无人员字段，操作人只进 operate_logs；users 表有账号但无列表 API、无门店归属。
  - 商品状态现状：在库/已定/已售/借出；库存汇总与 dashboard 按状态聚合。
- 已定方案（用户决策）：
  1. 调拨=两步制+**部分收货**：发出即离店（在途冻结）；验货相符项入库、不符项自动退回调出店，**差异原因必填**；单据可「部分完成」。
  2. 经办人=**可配置类别**（默认：店员(本店销售)/主播/代理/代销，可增删）必选、默认店员；具体人名可选自由填写。
  3. 位置=**门店下扁平库位主数据**（编号+名称+启停），商品存放位置与证书存放位置都从本门店库位下拉。
- **EPC 跨店关键约束**：EPC 是写入实物标签的终身码。调拨入库只改 products.store_id，**不重排 EPC、不重打标签**；EPC 中门店段语义明确为「首次配发门店」。因此：
  - EPC 格式合规性（正则）长期有效；「门店段=当前 store_id」一致性仅对从未调拨商品成立；
  - 规则化工具/盘点不得把跨店后 EPC 门店段不一致判为异常；扫码识别按 EPC 全局唯一匹配（现状 rfid-scan 即如此）。
- 版本：智能安防已占用 v1.0.7/dataVersion 1.0.7（已提交、未打包，工作区另有安防在制未提交改动）。本期变更顺延为 **v1.0.8/dataVersion 1.0.8**；含建表/加列，必须实现幂等迁移。平台已支持同一插件多版本并行试运行（commit 87a5fdf），发布槽位不再是硬阻塞，但 v1.0.8 打包仍应在安防在制改动收敛后进行。

## Functional Requirements

### 开单日期
- **FR-1**：销售开单默认业务日期为当天，开单人可改选为任意日期；单据列表与小票展示业务日期（系统创建时间不变）。

### 库位主数据
- **FR-2**：按门店维护扁平库位：编号（门店内唯一）、名称、排序、启用/停用；停用库位不能再被新选择，历史商品保留显示。
- **FR-3**：商品编辑时「存放位置」「证书存放位置」从**该商品所属门店**的启用库位中下拉选择，均可空。

### 证书查询
- **FR-4**：商品列表可一键筛选「未配证书」（cert 为空/纯空白）；可按存放位置（库位）筛选；支持按库位/证书位置关键词检索。

### 经办人
- **FR-5**：经办人类别为可配置基础数据（默认 店员(本店销售)/主播/代理/代销），可增、改名、停用，一个默认类别。
- **FR-6**：开单必选经办人类别（默认店员类别），具体经办人姓名可选填自由文本；单据保存类别名称快照（防止后续类别改名影响历史单），列表/详情/小票展示，支持按类别与经办人姓名筛选。

### 调拨
- **FR-7**：调出：在商品列表扫码（EPC）或勾选在库商品（可跨页累计，典型 10 件），选择调入门店（≠ 当前商品所属门店，一次一张单只允许同一调出店→同一调入店），提交即发出：商品转「在途」并在调出店冻结（不可开单/不可再次调拨/不可借出），库存从调出店「在库」扣减、计入「在途」。
- **FR-8**：调入：在「我接收的」列表打开在途单，逐件扫码或在清单上标记「相符/不符」；标为不符时**必须填写原因**（未到货/损坏/实物不符 或自定义文本）；完成验货后：
  - 相符项：store_id 改为调入门店、状态回「在库」、记入调入库存与入库日志；
  - 不符/未验项：自动退回调出门店「在库」、解冻，记退回日志与差异原因；
  - 全部相符→单据「已完成」；存在差异→「部分完成」。
- **FR-9**：调拨单列表区分「我发出的/我接收的」，展示单号、出入门店、件数、相符/差异数、状态、时间、操作人；详情含每件商品 EPC、名称、验收结果、差异原因。
- **FR-10**：所有调拨动作写 operate_logs 与 inventory_logs（transfer_out/transfer_in/transfer_back），不可删除已发生单据；商品跨店后 EPC 不变（见背景约束）。

## Non-Functional Requirements
- **NFR-1 迁移安全**：dataVersion 1.0.4→1.0.5 迁移幂等（加列/建表 IF NOT EXISTS、重复执行零副作用），不删改任何存量业务数据；存量 sales 经办人以默认类别「店员」回填、位置字段为空。
- **NFR-2 一致性**：同一张单的提交与验货必须在事务内完成库存状态变更，中途失败整体回滚。
- **NFR-3 并发安全**：已在途/非在库商品不能被重复发出（行状态校验，非法请求 400 且给出明确商品信息）。
- **NFR-4 三语**：所有新增界面文案走 i18n key（zh/en/it 三套齐全，不得出现硬编码中文裸串）。
- **NFR-5 兼容**：不破坏现有销售开单、借货、盘点、打印桥与对外 API 字段；新增字段均有默认值。

## Constraints
- **Technical**：FastAPI + sqlite3（db.py SCHEMA + migrate_schema alters 模式）；前端 Vue3 全局构建版（app.js/index.html/i18n.js，无构建工具）；EPC 现行规则 `前缀+门店段+品类码+6位hex`。
- **Business**：单租户多门店共库；实物标签终身不变；差异原因强制留痕。
- **Dependencies**：发布版本 v1.0.8 排在在制的智能安防 v1.0.7 之后；实施不依赖发布，工作区直接开发。

## Assumptions
- 差异原因候选项内置「未到货/损坏/实物不符」三个快捷项 + 可自由输入文本，不单独建差异原因表。
- 库位编号由用户手填（门店内唯一），不做自动编码规则。
- 经办人类别停用后历史单据正常显示，新单不可选；默认类别不可停用/删除（可改名）。
- 库位主数据与经办人类别管理入口放在现有「设置/基础数据」区域，不新增独立权限角色。
- 商品在途状态：库存汇总/dashboard 增加「在途」计数；在途商品仍归属调出店资产口径。

## Acceptance Criteria

### AC-1：开单日期可用（FR-1）
- **Type**: `rule`
- **Given**: 任一在库商品
- **When**: 新建销售单时不改日期直接保存；再建一单改选为 3 天前日期保存
- **Then**: 两单分别按当天与所选日期落 biz_date，列表与小票显示该日期，created 仍为实际创建时间
- **Pass Condition**: 8002 上两次开单后 GET /api/sales 两条记录 biz_date 分别符合预期
- **Evidence**: 接口响应与 sqlite sales 表行

### AC-2：库位主数据管理（FR-2）
- **Type**: `rule`
- **Given/When/Then**: 为总店新增库位「A-01 1号柜A层」→ 重复编号被拒；停用后商品表单下拉不可选但已引用商品仍显示该位置
- **Pass Condition**: 新增/重复拒绝/停用生效三项均有接口证据
- **Evidence**: /api/locations 响应与 products 详情

### AC-3：商品两位置字段（FR-3）
- **Type**: `rule`
- **Given/When/Then**: 编辑某总店商品，存放位置与证书位置下拉只出现总店启用库位；保存后重新打开值回显正确；换存到另一库位后旧库位可释放
- **Pass Condition**: 下拉门店隔离、保存回显、改存三处行为正确
- **Evidence**: /api/products/{id} GET 前后对比

### AC-4：无证书与库位筛选（FR-4）
- **Type**: `rule`
- **Given**: 库内存在 cert 有值与无值商品
- **When**: 商品列表使用「未配证书」筛选与按库位筛选
- **Then**: 未配证书结果全部 cert 为空/空白；库位筛选结果全部位于该库位（两个位置字段任一命中按界面文案明确区分）
- **Pass Condition**: 结果集 0 反例，计数与 SQL 直连一致
- **Evidence**: 列表接口响应 + sqlite 计数

### AC-5：经办人分类与落单（FR-5/FR-6）
- **Type**: `rule`
- **Given/When/Then**: 类别管理可增/改名/停用且默认=店员；开单默认带出店员、可改主播并填人名；保存后列表/详情/小票显示类别+人名；列表可按类别过滤
- **Pass Condition**: 默认值、改名后历史单保留旧名（快照）、筛选正确
- **Evidence**: /api/sales 与小票数据

### AC-6：调拨发出与在途冻结（FR-7/FR-10）
- **Type**: `rule`
- **Given**: 同一调出店 3 件在库商品（扫码 1 件+勾选 2 件）
- **When**: 选调入门店提交调拨；随后尝试对其中一件开销售单
- **Then**: 单状态=在途；商品 status=在途、store_id 不变；开单被 400 拒绝；不能重复调拨；汇总在途+3、调出店在库-3；logs 有 transfer_out；EPC 全程不变
- **Pass Condition**: 上述每一项均有证据
- **Evidence**: transfers/items/products/inventory_logs 表 + 开单报错

### AC-7：部分收货与差异退回（FR-8/FR-9/FR-10）
- **Type**: `rule`
- **Given**: AC-6 的在途单（3 件）
- **When**: 验货标记 2 件相符、1 件不符（原因必填，空原因时提交被拒）；完成验货
- **Then**: 2 件 store_id=调入店且在库、1 件留调出店在库；单据=部分完成、差异数 1 且原因落库；logs 含 transfer_in×2/transfer_back×1；调入/调出汇总各自正确；再次打开单据可查看不可重复验收
- **Pass Condition**: 库归属、状态、日志、单据状态、防重复验收全部正确
- **Evidence**: sqlite 直连 + /api/transfers/{id}

### AC-8：迁移幂等与数据无损（NFR-1/2/3/5）
- **Type**: `rule`
- **Given**: 含现有 100 商品/历史销售单的开发库副本
- **When**: 连续执行两次 1.0.4→1.0.5 迁移；再做一次调拨全流程
- **Then**: 两次迁移后表结构一致、存量行列数与关键字段零变化、sales 默认类别回填=店员；调拨事务中途异常时库存不变（构造一次非法验货验证 400 后状态保持）
- **Pass Condition**: 结构 diff 为空、存量零变化、事务回滚有证据
- **Evidence**: 迁移前后 sqlite 比对

### AC-9：端到端操作体验（FR-2~FR-9，NFR-4）
- **Type**: `rubric`
- **Dimension**: 界面完整度与操作顺畅度（库位管理、商品两位置、无证书筛选、经办人开单、扫码/勾选调拨、验货差异处理、三语文案）
- **Scale**: 1-5
- **Anchors**: 1=关键流程走不通或大量裸中文；3=主流程可用但入口隐蔽/反馈缺失；5=流程顺畅、状态反馈明确、zh/en/it 文案齐全无裸串
- **Pass Threshold**: >= 4
- **Evidence**: 浏览器走查截图/操作记录
