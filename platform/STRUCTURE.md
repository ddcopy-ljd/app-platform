# platform/STRUCTURE.md — 平台系统结构说明

> 本文件描述**平台核心**的系统结构与契约（网关路由映射、身份鉴权契约、隔离与部署安全、沙箱外网访问）。
> 强制开发要求以《AGENTS.md》为准；跨模块架构红线以根目录《AGENTS.md》为准。冲突时以 AGENTS.md 为准。

## 1. 访问地址与网关路由映射

为实现前后端分离、平台解耦以及插件的独立运行，系统 URL 路由被严格划分为**前端静态展示 (`/market/`)**、**前端业务载体 (`/app/`)** 和 **后端 API 网关 (`/gw/`)** 三条链路（红线见根目录 AGENTS.md §3.2）。

### 1.1 推广页路由（前端静态）

此类路由不经过业务应用进程，由平台直接伺服静态文件：

- **`/market/{插件ID}/`**：公开展示地址。无需登录即可访问，主要用于外部营销和应用市场展示。始终自动指向**当前正式版本**的推广页，版本切换后自动更新。
- **`/market-preview/{插件ID}/{版本号}/`**：沙箱预览地址。需要登录平台管理员账号才能访问，用于管理员在正式上线前预览试运行版本的推广页。

### 1.2 业务工作区路由（前端页面）

此类路由用于加载插件的前端单页应用（SPA）代码：

- **`/app/{插件ID}/login`**：插件独立的统一认证与登录页面。
- **`/app/{插件ID}/{租户ID}/`**：企业专属工作区。平台通过新开网页跳转至此，并在 URL 参数中传递平台签发的身份鉴权 Token 供前端获取。

### 1.3 API 网关透传路由（后端服务 `/gw/`）

这是前端页面向底层插件进程发起 API 调用的唯一通道。**底层开发人员无需在代码中处理 `/gw/` 前缀或复杂的租户路径拼接**。

- **正式运行网关：`/gw/{插件ID}/***`
  - 网关动作：平台网关在内部查库定位到当前正式版本进程的监听端口（如 `10001`）。
  - 路由剥离与透传：网关剥离前缀，反向代理为 `GET http://127.0.0.1:10001/*`。网关**不解析**租户身份，原封不动透传前端携带的 HTTP Headers（包含插件业务 Token）。
- **沙箱试运行网关：`/gw-preview/{插件ID}/{版本号}/***`
  - 作用：用于试运行期间的 API 调用，网关会将请求代理到该特定测试版本对应的独立端口进程上。

## 2. 平台环境与身份鉴权契约

为实现平台与插件的彻底解耦，系统采用「平台免密凭证 (SSO Token) + 插件原生凭证 (Business Token)」双轨制鉴权。插件的 FastAPI 后端必须同时支持这两种凭证的解析与换签（红线见根目录 AGENTS.md §3.3）。

### 2.1 凭证流转双轨制

**轨道 A：平台单点/穿透跳转（平台下发 SSO Token）**
- 场景：新企业注册后无缝跳转进入插件、平台管理员进入试运行沙箱、管理员排障穿透进入真实环境。
- 机制：平台在打开新网页（`/app/{插件ID}/{租户ID}/`）时，会在 URL 参数中附带平台签发的 SSO Token。插件前端获取后发送给插件后端；插件后端全局拦截器校验该 Token 合法性，直接免密放行（并建议在此时换签为插件自身的 Business Token 下发给前端）。

**轨道 B：业务用户日常登录（插件自发 Business Token）**
- 场景：普通员工日常直接访问 `/app/{插件ID}/login`，输入账号密码登录。
- 机制：此过程平台完全不介入。插件后端验证账号密码通过后，调用平台内网 API 核对功能订阅状态，随后签发插件自己的 Business Token，供后续 API 请求使用。

### 2.2 平台 SSO Token Payload 结构

当处于轨道 A 时，平台签发给插件的免密 Token 格式如下：

```json
{
    "iss": "saas-platform",
    "iat": 1704067200,
    "exp": 1704070800,               // 平台 Token 有效期极短（如 5 分钟），仅供一次性跳转换签用
    "sub": "user_8848",              // 访问主体：真实业务用户ID 或 平台管理员ID
    "tid": "xc-2024-001",            // 租户标识 (Tenant ID)：用于动态切换数据库
    "mode": "NORMAL",                // 操作模式：NORMAL | SANDBOX | PRODUCTION_SUPPORT
    "role": "TENANT_ADMIN"           // 角色标识
}
```

### 2.3 三大鉴权模式的插件响应约定

三种运行模式（NORMAL / SANDBOX / PRODUCTION_SUPPORT）的响应约定见根目录 AGENTS.md §3.4。

## 3. 隔离与部署安全建议

目前通过 `/app/...`、`/gw/...` 路径打开的插件服务页面和平台管理后台处于**同一个主域名**下，平台暂未在物理层面做同源隔离。这意味着插件页面的脚本在理论上有能力读取到平台管理后台保存在浏览器里的顶级登录令牌。

虽然现阶段所有插件都由系统管理员人工审核并手动上传，在演示环境下风险可控，但为了保障生产环境的绝对安全：

👉 **强烈建议：** 正式上线前，应将平台主站（管理后台）与业务工作区（`/app/` 和 `/gw/`）拆分部署至不同的子域名下，利用浏览器的同源策略（SOP）彻底阻断跨站点脚本（XSS）的越权风险。

## 4. 远程沙箱环境外网访问指南（开发调试用）

本项目的开发与预览通常运行在远程沙箱环境中。沙箱默认不直接开放公网端口，`localhost` 仅在沙箱内部可达，开发人员无法直接用本地或手机浏览器访问沙箱内启动的服务。本节记录一套**经实战验证**的外网暴露方案，供开发调试、移动端预览、对外演示时使用。

### 4.1 环境特征与约束

- 沙箱出站流量统一走 HTTP 代理（如 `http://127.0.0.1:18080`），直连可能被拦截。
- 代理支持 `CONNECT` 隧道到多数标准 HTTPS 域名（如 `*.serveo.net:443`、`*.trycloudflare.com:443`），但对部分隧道服务的专属协议（QUIC/WebSocket 升级）可能不兼容。
- 沙箱未预装 `ngrok`、`cloudflared`、`frp` 等隧道工具，需按需下载或使用系统自带能力。

### 4.2 推荐方案：SSH 反向隧道（serveo.net）

> 此方案**无需注册账号、无需额外安装**，复用系统自带的 `ssh` 与 `nc`，经代理 CONNECT 隧道建立反向端口转发，可稳定获得一个公网 HTTPS 地址。

**前置条件**：沙箱内已用 `0.0.0.0` 绑定并启动目标服务（例如 FastAPI 监听 `8000`、Python `http.server` 监听 `8888`）。

**完整命令**（把 `<LOCAL_PORT>` 替换为你的服务端口）：

```bash
ssh -o StrictHostKeyChecking=no \
    -o UserKnownHostsFile=/dev/null \
    -o ProxyCommand="nc -X connect -x 127.0.0.1:18080 %h %p" \
    -p 443 \
    -R 80:localhost:<LOCAL_PORT> \
    serveo.net
```

**参数说明**：

| 参数 | 作用 |
| --- | --- |
| `-o ProxyCommand="nc -X connect -x 127.0.0.1:18080 %h %p"` | 让 SSH 经沙箱 HTTP 代理的 CONNECT 通道连接 serveo.net，绕过直连限制。 |
| `-p 443` | serveo.net 在 443 端口提供 SSH 服务，避免 22 端口被封。 |
| `-R 80:localhost:<LOCAL_PORT>` | 把 serveo 的 80 端口反向转发到沙箱本地服务端口。 |

**成功输出示例**：
```
Forwarding HTTP traffic from https://xxxxxxxxxxxx.serveousercontent.com
```
输出中 `https://*.serveousercontent.com` 即为**公网可访问地址**，可直接在手机或任意浏览器打开。

### 4.3 备选方案

- **cloudflared Quick Tunnel**：`cloudflared tunnel --url http://localhost:<PORT> --protocol http2`。需手动下载二进制，且部分代理下请求 `api.trycloudflare.com` 可能超时，作为备选。
- **localtunnel (Node.js)**：`npx localtunnel --port <PORT>`。依赖 WebSocket，在严格代理下偶发连不上，作为备选。
- **IDE 内置预览面板**：仅适合在 IDE 内查看，无法分享给外部设备或第三方，不能替代公网地址。

### 4.4 使用注意事项

1. **临时性质**：上述隧道均为临时通道，沙箱或隧道进程重启后地址会变化，**不可作为生产环境入口**。
2. **安全提示**：公网地址暴露期间，任何人都可访问，调试含敏感数据的服务时务必加鉴权或及时关闭隧道。
3. **端口绑定**：服务必须绑定到 `0.0.0.0`（不能仅 `127.0.0.1`），否则反向隧道无法转发到本机服务。
4. **关闭方式**：在沙箱中按 `Ctrl+C` 终止 SSH 进程即可关闭公网访问。
